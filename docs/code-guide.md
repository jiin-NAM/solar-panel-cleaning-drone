# DA-DAKA 핵심 코드 이해하기

DA-DAKA의 자율 청소는 크게 네 단계로 이해할 수 있습니다.

**보고(인식) → 찾아가고(경로계획) → 정확히 맞추고(정렬) → 안전하게 물을 쏜다(분사)**

각 기능은 ROS 2 / Raspberry Pi 5 / PX4로 나뉘어 동작합니다. 여기서는 실제 프로젝트에 사용된 기능과 설정을 **실행 순서 중심**으로 설명합니다.

## 1. 드론이 지금 무엇을 할지 정하는 코드 — FSM

처음부터 분사까지 한 번에 실행하는 것이 아니라, **Finite State Machine(FSM)** 으로 작업 상태를 구분했습니다.

| 상태 | 사람에게 설명하면 | 다음 단계로 넘어갈 조건 |
|---|---|---|
| SURVEY | 작업할 패널을 찾아봅니다 | 관측 데이터 확보 |
| MAP | 패널의 위치를 정리합니다 | 위치 지도 생성 |
| ROUTE | 어느 패널부터 갈지 결정합니다 | 방문 순서 계산 |
| APPROACH | 선택한 패널 쪽으로 접근합니다 | 근접 대상 확보 |
| PRECISION_ALIGN | 물을 쏠 위치에 정확히 맞춥니다 | 거리·자세·조준점 정렬 |
| SPRAY_CONFIRM | 분사 조건을 한 번 더 확인합니다 | 안전 허가 |
| SPRAY | 정해진 시간 동안 밸브를 엽니다 | 분사 종료 |
| VERIFY | 다시 촬영해 오염이 남았는지 확인합니다 | 다음 패널 또는 재시도 |

핵심은 **정렬 완료와 분사 실행을 분리한 것**입니다. 실제 상태 전이는 \`PRECISION_ALIGN → SPRAY_CONFIRM → SPRAY\` 순서로 설정되어 있습니다.

## 2. 움직이는 드론의 영상과 위치를 맞추는 코드 — Capture-Sync

드론이 움직이는 도중 영상이 촬영되고, AI가 결과를 반환하기까지는 시간이 걸립니다. 그래서 AI 결과가 **도착한 시각**의 드론 위치를 사용하면 목표 패널의 위치가 어긋날 수 있습니다.

이를 막기 위해:

1. 카메라가 **촬영 timestamp**를 기록합니다.
2. 기체 Pose와 LiDAR Range를 history buffer에 저장합니다.
3. 해당 촬영시각과 가장 가까운 센서 데이터를 찾습니다.
4. 패널 중심 픽셀, 기체 위치·자세, 거리, 카메라 장착 오프셋을 결합합니다.
5. 관측한 패널을 **Local 좌표**로 변환하고 Panel Map에 저장합니다.

실제 설정은 \`capture_sync_tolerance_s = 0.15\`, \`input_history_s = 2.0\`입니다. 동기화가 불가능한 관측은 위치 지도 계산에 사용하지 않습니다.

## 3. 어떤 패널부터 방문할지 정하는 코드 — NN + 2-opt

Panel Map에 패널 좌표가 들어오면 방문 순서를 계산합니다.

**Nearest-Neighbour(NN)** 는 현재 위치에서 가장 가까운 패널을 찾아 차례대로 방문 순서를 만듭니다. 구현이 단순하고 빠르지만 불필요하게 돌아갈 수 있습니다.

**2-opt** 는 NN이 만든 경로의 일부 구간을 뒤집어서 총 이동거리가 더 짧아지는지 비교합니다. 개선되는 변경을 적용하여 경로의 교차와 이동거리를 줄입니다.

**입력:** 패널 위치 좌표 및 현재 위치  
**출력:** 자율비행에 사용할 패널 방문 순서

고정된 P01→P02→P03이 아니라, 촬영한 현장 데이터로 목표 순서를 계산하는 방식입니다.

## 4. 오래된 AI 결과를 걸러내는 코드 — PerceptionResult.msg

AI 서버가 보내는 결과에는 오염 좌표뿐 아니라 다음 식별 정보가 포함됩니다.

| 정보 | 역할 |
|---|---|
| \`source_id\`, \`session_id\` | 현재 장치·임무에서 온 데이터인지 확인 |
| \`frame_id\`, \`sequence\` | 어떤 영상과 순서의 결과인지 식별 |
| 촬영 \`timestamp\` | 실제 촬영시각 유지 |
| \`result_age_s\` | 시간이 너무 오래 지난 결과인지 확인 |
| 패널·오염 좌표 | 실제 목표 위치 및 세척 여부 판단 |

예전 영상의 오염 위치를 **지금 위치로 착각해 분사하는 문제**를 예방하기 위한 처리입니다.

## 5. 패널에서 약 1m를 유지하는 코드 — TF-Luna 거리제어

TF-Luna LiDAR 데이터 처리 순서:

\`0x59 0x59 헤더 → 9-byte checksum → 측정 범위·신호 유효성 → Median(5) → Moving Average(5) → /distance/filtered\`

필터링한 거리를 목표 **1.0m**와 비교하고, 외부 거리 PID가 기체의 속도 명령을 조정합니다. 속도·가속도 제한도 적용하여 한 번의 센서 이상값이 급격한 이동 명령으로 이어지지 않게 했습니다.

## 6. 아무 때나 물이 나오지 않도록 하는 코드 — Safety Gate

**오염을 검출했다고 바로 분사하지 않습니다.**

분사 전에 다음을 함께 확인합니다.

- LiDAR 거리와 센서값 유효성
- 영상 조준점과 Yaw 정렬
- 기체 자세·속도 안정성
- AI 결과의 최신성
- 통신 및 구동장치 상태

모두 충족한 경우에만 \`/spray/trigger\` 명령을 전달합니다.

**명령 전달 흐름**

\`MAVROS CommandLong → PX4 Camera Trigger → FMU AUX5 → DRV8876 → NC Solenoid\`

분사 제어 설정에는 \`output_enabled: false\`, \`pulse_duration_s: 3.0\`, \`maximum_pulse_s: 3.0\`가 사용됩니다. 기본적으로 분사 출력이 차단되며, 허가된 동작도 **3초**로 제한됩니다. 조건이 깨지면 즉시 밸브를 닫고 HOLD 또는 재정렬 상태로 전환합니다.

## 7. 물을 쏠 때 기체가 밀리는 현상을 줄이는 코드 — Feed-forward

물줄기는 기체에 반작용을 줍니다. 이를 예상하여 분사 시작과 동시에 **Feed-forward 보상 속도**를 추가합니다.

- 분사 전: LiDAR 거리 Feedback으로 작업거리 유지
- 분사 중: 거리 Feedback + Feed-forward 보상
- 분사 후: Feed-forward를 해제하고 Feedback으로 남은 거리오차 보정

적용한 설계 수치:

| 항목 | 값 |
|---|---:|
| 추정 유체 반력 | 약 0.437N |
| 외란가속도 | 약 0.156m/s² |
| 계산 FF 명령 | 약 −0.031m/s |
| FF 보상 출력 제한 | 0.20m/s |
| 최종 수직속도 제한 | 0.25m/s |

## 8. 실제로 청소되었는지 다시 확인하는 코드 — Fresh Verify

분사를 끝냈다는 사실과 오염이 제거되었다는 사실은 다릅니다.

1. 밸브를 닫습니다.
2. 기체의 거리·자세를 안정화합니다.
3. **분사 이후 새 프레임**을 획득합니다.
4. 새 프레임으로 오염 영역을 다시 분석합니다.
5. 잔류 오염 여부에 따라 재정렬·재분사 또는 다음 작업으로 전환합니다.

이전 프레임이나 오래된 AI 결과는 검증에 다시 사용하지 않습니다.
